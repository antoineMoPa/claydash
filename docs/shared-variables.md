# Shared vector variables

Create points with **Add point** in the command palette or through MCP. The command creates a World point at the 3D cursor. Points appear alongside objects in the object list. Select a point there or in the viewport to move it. Double-click an object or point name to rename it; its row menu also offers Rename. Point row menus provide coordinate space and deletion. Select an object and use **Variable bindings** at the bottom of its inspector to link its object position, group position, or Bézier control points to a point. World coordinates let points on differently positioned, rotated, or scaled objects meet at one shared location; local coordinates reuse the same coordinates in each object's own frame.

A new link preserves the current point using an offset. Click **Use vector point** to clear that offset and place the point directly at the variable. Select the orange point in the viewport, then use the regular movement gizmo or press **G** to grab it. The regular X/Y/Z constraints apply to G grabs. Every linked point follows. Escape cancels movement; clicking elsewhere returns to object editing. Points remain available with the inspector closed. The object-list name filter includes shapes, points, and cameras; matching descendants keep their ancestor rows visible. The inset X clears the filter. Local point handles use the selected linked object's coordinate frame, otherwise the first saved binding's frame; unbound points use the world frame. Offsets use the variable's coordinate space. Changing the coordinate space reinterprets the existing numeric values.

Variables and links are saved with the scene, and their edits participate in Undo/Redo. Unlinking a point or deleting a variable keeps its last evaluated coordinates. Linked positions are constrained, so direct transform edits and position animation cannot override them until unlinked. Position controls in the inspector are disabled while linked; other transforms and unlinked curve points remain editable.

Curve point links refer to point numbers. Unlink affected points before inserting or removing curve anchors, then reconnect the resulting points. Variable values currently support vectors only; variable animation, arithmetic expressions, links to scalar parameters, and automatic propagation of links to duplicated objects are not implemented.

Open **File → Examples → Single-wheel suspension** to explore a double wishbone linkage. Select **Wheel travel - drag Y** in the object list or viewport, press **G**, then **Y** and move the point. The lower and upper ball joints follow a planar four-bar constraint: both wishbones and the upright keep their lengths, the chassis pivots stay fixed, and the wheel rotates with the upright as camber changes. Travel is limited to −0.65 through +0.65 scene units. The damper's fixed-length body and shaft rotate toward their opposite mounts and telescope through their overlap. Escape cancels movement, and Undo restores a completed move. The example saves ten World points, five position bindings, 28 rigid pose bindings and one four-bar constraint. Ball joint points are solver outputs; move the travel point to articulate the assembly. This models the linkage geometry, without forces or spring dynamics. The example uses Deferred rendering with Mesh (Poisson) selected on the chassis group; use **Recompute** to build its mesh, and rebuild after point edits when a new mesh is wanted. Mesh caches exist only for the current session and are not saved in the project. MCP can build and inspect the cache with `build_poisson_mesh {id: root_uuid}` and `get_poisson_mesh_status`.

MCP exposes `variables: {vectors, bindings, rigid_bindings, four_bar_constraints}` directly in `get_state`, with typed actions in `apply`. Create a vector with `CreateVectorVariable` (`name`, `value: [x,y,z]`, optional `space: "World" | "Local"`; MCP defaults to World). The response includes `created_variable_ids`. Supply an optional UUID `id` when creating and binding in the same transaction:

```json
{"actions":[
  {"type":"CreateVectorVariable","id":"00000000-0000-0000-0000-000000000001","name":"Anchor","value":[1,2,3]},
  {"type":"SetVectorBinding","object":"OBJECT_UUID","target":{"BezierPoint":0},"variable":"00000000-0000-0000-0000-000000000001"}
]}
```

Targets are `"Position"`, `"GroupPosition"`, or `{"BezierPoint": index}`. `SetVectorBinding` replaces the link for that target; its optional `offset` defaults to `[0,0,0]` in the variable's space. Use `UpdateVectorVariable` with `id` and optional `name`, `value`, or `space`; `RemoveVectorBinding` with `object` and `target`; or `DeleteVectorVariable` with `id`. Unlink and delete retain evaluated coordinates. `SetVariables` replaces the complete typed `variables` state (vectors require id/name/value, bindings require object/target/variable/offset). Include `expected_revision` from `get_state` for stale edit protection. The whole batch validates and commits as one undoable edit; invalid references, duplicate IDs/targets, invalid curve indices, nonfinite values, and singular World coordinate frames reject the entire batch.

Use **Rigid transform** at the bottom of the object inspector to edit a rigid pose link. Choose the Object or Group frame, named World points for **Origin** and **Aim**, and either an Up point or a World direction. **Select** selects the referenced viewport point so its regular movement gizmo and G grab can be used. Expand **Local anchors** to edit the object's local origin, aim and up points. **Capture current pose** derives these anchors from the current pose; new links capture automatically once their references are complete. Click **Add rigid transform** or **Apply rigid transform** to commit the draft. Invalid frames leave the scene unchanged. **Reset** discards a pending edit; **Remove** retains the evaluated pose. Changes support Undo/Redo. Unlink conflicting position or curve-point bindings before adding a rigid transform.

MCP rigid pose links use `SetRigidBinding` with a `binding` containing `object`, `target: "Object" | "Group"`, World point IDs `origin` and `aim`, `up: {"WorldDirection": [x,y,z]}` or `{"Point": "UUID"}`, and authored local points `local_origin`, `local_aim`, `local_up`. The origin sets position; the heading and independent up direction set rotation. Shape parameters and scale remain fixed. The two target points do not stretch the object to their separation. Parent transforms require positive uniform scale without shear. A rigid pose and position binding cannot share a target. `RemoveRigidBinding` takes `object` and `target`, retaining the evaluated pose.

`SetVariables` additionally accepts optional `rigid_bindings` and `four_bar_constraints` arrays; older vector-only scenes remain compatible. A `PlanarFourBarConstraint` uses World point IDs `driver`, `lower_pivot`, `upper_pivot`, `lower_joint`, `upper_joint`, positive `lower_length`, `upper_length`, `upright_length`, and numeric `driver_y_offset`, `travel_min`, `travel_max`, with `branch: "Positive" | "Negative"`. The solver uses the positive-X lower-arm arc in the World XY plane, keeps all link lengths fixed, computes the upper joint from intersecting circles, and clamps driver Y to the authored feasible range. Driver X/Z do not affect this planar linkage. Output joint points are read-only; move the driver to articulate it. Parent/child pose links and derived point dependencies settle in order; invalid references, ambiguous frames, impossible travel ranges, duplicate outputs, shared drivers, and cycles reject MCP transactions atomically. Removing links or deleting referenced points retains evaluated geometry and points. Constraint reference points require World coordinates.
