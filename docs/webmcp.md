# Browser agent tools (WebMCP)

The browser editor registers tools with `document.modelContext` when the browser supports WebMCP. The editor remains usable without that API. For local testing in Chrome, enable `chrome://flags/#enable-webmcp-testing` and relaunch. Chrome DevTools can list and invoke the tools in Application → WebMCP. The Chrome DevTools MCP server exposes `list_webmcp_tools` and `execute_webmcp_tool` when started with `--categoryExperimentalWebmcp`. See [Chrome's WebMCP guide](https://developer.chrome.com/docs/ai/webmcp) and [DevTools instructions](https://developer.chrome.com/docs/devtools/application/webmcp).

The page exposes scene summary and command-list reads; primitive creation; undo and redo; editable mesh create/edit/read; section mesh preview and create/edit; and viewport captures. Mesh actions are atomic and undoable. `claydash_apply_mesh_actions` accepts actions with the same geometry meanings as the desktop agent API: local vertices, zero-based triangle faces, `Auto`/`Flat`/`Smooth` shading, and per-face-corner UVs. `SetMeshTexture` accepts a base64 PNG after UVs have been set for every face. It validates a square power-of-two image from 64 through 4096 pixels and a decoded PNG size of at most 64 MiB. `claydash_get_mesh` returns texture metadata, not the full image bytes.

`claydash_export_project` returns the current editable project as `{ "format": "claydash", "byte_length": N, "data_base64": "..." }`. Decode `data_base64` to write a `.claydash` file, or pass it directly to `claydash_open_project`. The bytes use the same serialization as the editor's Save command, including editable meshes, UVs, and baked textures. The reported `byte_length` is the exact decoded byte count. Projects larger than 32 MiB return an error with their size; the tool never truncates a document. `claydash_open_project` replaces the current scene from up to 32 MiB of decoded `.claydash` data supplied as base64. `claydash_set_view` positions the camera for inspection.

`claydash_capture_viewport` returns a PNG cropped to the viewport. `claydash_capture_multi_angle` returns a 2×2 PNG sheet (front, side, top, three-quarter), temporarily moving the viewport camera and restoring its original position, target, and up vector. It accepts optional four camera `views` and a canvas-pixel `[x,y,width,height]` `crop`; each tile preserves the source aspect ratio. Both capture tools temporarily hide editor controls and gizmos, then restore them. Each image includes a view title, an axis marker, and a scale bar measured in Claydash world units at the camera target depth. Perspective objects closer or farther from the camera have a different apparent scale. These are browser canvas captures, so the page must have a working WebGPU adapter and finish rendering; headless browsers without an adapter cannot provide useful images.

The web canvas reduces device scale in high-DPR windows when its backing area would exceed one million pixels. It keeps a minimum scale of 1 so viewport coordinates remain consistent; a large window can therefore exceed one million backing pixels. CSS fills the browser window, and pointer positions use the same effective scale. WebMCP captures use the canvas resolution.
